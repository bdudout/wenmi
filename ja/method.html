同じラテン文字でも、暗号方式は異なる

公開電碼は符号化の段階であり、秘密そのものではない。1916年の文密は、二つの固有の表で音節に変換する。

  1. ロザモンド · 1915–1916

    英語→文字を相互に置換

    you ↔ hea

    一文字を別の文字に置き換える。同じ表で暗号化と復号を行う。

  2. 中文電碼

    漢字→公開の4桁番号表

    文 → 2429

    公開の表なので、これだけでは内容を隠せない。

  3. 圧縮符号 · 複数の表

    4桁の中文電碼→2桁ずつの数 → 音節

    00–99 → CV

    方式ごとに表が異なる。CVは子音と母音を表す。

  4. 文密 1916 · G0 / Y0

    4桁の中文電碼→二つの異なる音節表

    報 → 1032 → fa | zi

    G0のみの例。Y0は別の表なので、相互に代用できない。

要点：暗号方式

1916年の二つの系統は、いずれも5つの操作で暗号化されている。現代的な意味での秘密鍵はない。東京 → 肇慶の系統（1916年6〜9月）を例にとる。

中国語の本文報
公開の電信符号1032
二つに分ける10 | 32
半分ずつ → 音節（G0 表）fa | zi
音節をつなぎ、10文字ずつに区切るfazihipego

G0 表は、00〜99 の各数に「子音＋母音」の音節を一つずつ割り当てる。子音は h から始まるアルファベットの逆順（h g f d c b z y x w v t s r q p n m l k）で、十の位ごとに二つ。母音 a e i o u が一の位を表し、組の最初の子音では昇順、二番目の子音では降順に並ぶ（蛇行配列）：

つまり ha = 00、hu = 04、gu = 05、ga = 09、fa = 10……ka = 99。Python で書けば：

ORDER, V = "hgfdcbzyxwvtsrqpnmlk", "aeiou"
G0 = {c + v: 10 * (i // 2) + (j if i % 2 == 0 else 9 - j)
      for i, c in enumerate(ORDER) for j, v in enumerate(V)}

def decode(letters):          # "fazihipego..." -> ["1032", "0278", ...]
    s = [letters[k:k+2] for k in range(0, len(letters), 2)]
    return ["%02d%02d" % (G0[a], G0[b]) for a, b in zip(s[::2], s[1::2])]

各電報は署名「伸」（heyu = 0135）、ときに「伸令」で終わり、その後に日付が続く。日付は韻目代日（巧 18日、漾 23日、元 13日……）か、漢数字（卅 30日）で書かれる。

試してみる

電報を選び、漢字をクリックするか一字ずつ再生すると、対応する二つの音節が、暗号文と、電報の下に表示される鍵の表で強調表示される。二つの系統（G0、Y0）を選べる。オレンジの破線で囲まれた字は疑わしい字（用紙の判読が不確か、または稀な字）である。

各枠：音節 · 電信符号 · 漢字。

出発点：公開済みの研究

出発点は「Sun Yat-sen's circle on the wire, 1916–17」[1]とリポジトリ dbourdeau/cyphersolver[2]である。そこでは電報用紙の翻字と、孫文周辺の約60通の電報の解読が公開されている。これらの電報は、S. Tomokiyo 氏が Cryptiana で紹介した山田純三郎の「圧縮表」[8]の系統に属する表を用いる。子音20・母音5、すなわち00〜99の各数に一つずつ対応する100音節である。

趙伸の暗号電報はこれと異なる。10文字の語で加算の跡は見えず、そこでは未解決の問題とされていた[1]。軍務院系統の電報の多くは平文の前置き 2429 1378 で始まり、「文密」と読める。これがこの暗号の名である。雲南宛ての電報は同じ構造で母音が6つあり、標識「Cg」で始まる。私たちは特定済みの文書と翻字、そして電碼の半分が1音節になるという考え方から出発した。以下に示すとおり、東京発の系統では表は単純な規則に従っている。アルファベットの逆順、10ごとに子音二つ、母音の蛇行配置である。

ルール

歴史的暗号の解読は、自分自身をだますのに格好の場である。パラメータが十分にあれば、どんな雑音の中にも中国語を「読める」。そこで私たちは、あらかじめ定めたルールの下で作業し、追記のみのログ（約1,400行、31回のセッション）に記録した。

  • 史料は改変しない。JACAR の PDF はダウンロードしたまま保存し、SHA-256 を記録する。新しい読みはすべて新しい版のファイルとする。
  • 検証用電報を一つ。0406号電報（1916年7月12日）は、鍵の調整にも読みの修正にも一度も使わない。判定にのみ用いる。
  • クリブ（推測平文）は使わない。推測した語（人名や決まり文句）を平文に押しつけたことは一度もない。アンカーとして用いたのは、日本の職員が用紙に平文で書いた日付だけであり、複数のアンカーの組を試した。
  • 正の対照と零の対照。探索は毎回、同じ形式の既知の鍵で暗号化した既知の中国語文（ソルバーは鍵を復元できなければならない）と、シャッフルしたデータ（何も見つけてはならない）でも実行する。記録上のスコアは、この二つの基準と比べて初めて意味を持つ。
  • 複数の乱数シード。異なる初期値から同一の最適解が得られた場合のみ採用する。
  • 状態の明示。各結果には、事実・仮説・否定的試行・候補・裏付けあり、のいずれかを付す。

本文と限界を確認する

暗号文は日本の職員による手書きの写ししか残っていない。g と q、x と d、u と n は混同しやすく、一字の誤りで漢字が一つ変わり、一字の脱落でそれ以降の全体がずれる。

  • 独立した人間の読み：私自身が小さなローカルのインターフェースで各語を読んだ。断片は匿名化・シャッフルして提示され（どの電報のどの位置かはわからない）、JSON で書き出せる。約15回、数百の断片。一部の回は特定の文字に絞り、同じ筆写者の確かな字例を比較用に添えた。

ある読みの細部が決定的だった。長いあいだ q は g の字形の異体とみなされていた。人間の読みがこれを区別したことで、アルファベットはちょうど20の子音（b c d f g h k l m n p q r s t v w x y z、j なし）になった。当時の最良のモデルでは、この区別だけでスコアが681から829に上がった。

表明しておくバイアス

私の読みのうち2回（「支援付きの読み」と、疑わしい16符号の再読）はブラインドではなかった。私はモデルの提案を知っていた。リスクを抑えるため、各電報の最後の4単位（署名と日付）はこの方法では変更できないこととし、検証用電報0406には一切手を触れず、すべての提案は画像上で確認することを条件とした（採用18、却下27）。

第2段階 ―― うまくいかなかったこと（とその理由）

30回のセッションを通じて、私たちは未知の換字式暗号に対する古典的な方法をとった。

  • 言語モデル（電信符号の1-gram・2-gram）。ウィキソースにある孫文の著作約43万字を符号化して学習し、のちに刊行された1916年の電報で補った。
  • 未知の表「音節 → 数字」（100マス、自由に配置）を焼きなまし法で探索。マルチスレッドの C++ エンジンで、初期値64 × 3,000万回の反復、続いて反復局所探索。8コアで1回あたり約12分。
  • アンカー：用紙の日付から導いた、電報末尾の韻目。

これらの探索はすべて失敗し、対照がその理由を教えてくれた。ソルバーは正の対照の鍵を復元できた（たとえば267符号中258）。つまり能力はあった。だが記録上の最良スコア（約900）は本物の文章（1,200〜1,350）に遠く及ばず、一方でシャッフルしたデータ（約670）ははっきり上回っていた。任意のコードブックで暗号化した文章は810〜940となる。記録はまさにそのように見えた。

仮定の中に二つの誤りが潜んでいた。

  1. 誤ったアンカー。16日から30日について、韻目代日は当初想定したものとは別の声調の系列を用いる（刊行された孫文の原電で確認[11]）。そのため複数のアンカーが誤っていた。
  2. 鍵空間が広すぎた。自由に配置できる100マスの表には、900前後の雑音の最適解を作り出すだけの自由度がある。逆の実験がこれを裏付ける。最終的に見つかった構造を緩めると（実験 E21）、当てはまりは良くなるが検証用電報は読めなくなる。過学習である。

並行して、文献の手がかりも最後まで追った。在漢口日本総領事館の報告（1916年5月9日・11日）[5][6]は、「111を加える」、続いて「4桁を逆順にして111を加える」という再暗号化を記している。報告に添付された4月の電報は確かにその方法で解ける（算術的な繰り上がり、末尾に韻目）。しかし東京発の系統では、±111 のあらゆる変種――逆順の有無を問わず、音節表の下で生じる残差のずれも含めて――が否定的だった（実験 E13、E15、E16）。結論：7月の電報には加算鍵はない。

第3段階 ―― 鍵を使わない検定：子音が十の位を表す

転機は、鍵をまったく探さない検定からやってきた。電信符号には独特の形がある。千の位の数字は偏っており（常用符号はほとんど 0000〜7999 にあり、8xxx や 9xxx はまれ）、一の位はほぼ一様である。符号の半分（2桁）が一つの音節になるのなら、問題は音節のどの部分が十の位を担うのかである。

そこで、電報内の位置ごとに文字を数えた（実験 S3）。符号の前半（千の位と百の位）を担う位置では、子音の分布が極端に偏っていた（z ≈ 22）。h と g が支配的で、l、p、m は一度も現れない。一方母音は一様だった（z ≈ 1）。シミュレーション（S4）によれば、ランダムな表がこのパターンを生むことはない（400回中0回）が、子音が十の位、母音が一の位を表す座標表なら再現できる。

この仮説（H9）は探索空間を劇的に狭める。100の音節を自由に置くのではなく、各子音を十の位に、各母音を数字に割り当てるだけになるからだ。また、日付アンカーのいくつかの組がありえないこともわかった。H9 の下では、想定した韻目の一部が、同じ子音を二つの十の位に対応させることを要求してしまう。

第4段階 ―― 制約付きソルバーと検証用電報

新しいソルバー（anchor_coord）は座標表だけを探索する。アンカーなしでは正の対照すら解けないが、正しいアンカーが10あれば鍵全体を復元できる。そこで H9 と両立するアンカーの組（324組中97組）を列挙し、最も妥当なものを試した。一組だけが抜きん出た：D = {6月23日 漾、7月18日 巧、7月19日 皓、9月13日 元}。

判定役は、探索から外しておいた0406号電報である。言語モデルの下で、平均的な字に対する1字あたりの対数尤度の平均利得を測る。解読結果が中国語らしければ正、そうでなければ負になる。表 D はコーパス v4 で1字あたり +1.9、コーパス v5 で +3.47 を示した。他の候補表はすべて0以下、零の対照の表は −1〜−2.5 である。交差検証（S7：5通で鍵を求め、6通目で判定）でも、6通中6通で表が転用できた。文章は句ごとに読めるようになる：三十式槍、萬一千、軍用品已到門司、年息一割、無擔保、第二批械、軍務院、豫定計畫……

第5段階 ―― G0 表

当てはめた表を1マスずつ眺めると、規則性が目に飛び込んでくる。子音はアルファベットの逆順に、十の位ごとに二つずつ並び、母音は上がってから下がる。外れている少数のマスは、データによる制約が弱かったところだ。そこで当てはめた表を、それが近似している規則的な表に置き換える。これが G0 であり、もはや自由なパラメータは一つもない。

結果は、本研究で最も強い検証となった。まったく調整せずに、G0 は検証用電報0406を1字あたり +3.99 で解読する。元になった当てはめの表（+3.48）よりも良い。当てはめでぼやけた表が、その中に隠れていた単純な規則に及ばない。規則こそが本当の鍵なら、まさにそうなるはずである。G0 は7通すべての351符号を与え、電報の末尾も一貫したものになる。署名「伸」の後に日付（6月23日は「漾」、7月18日は「巧」、9月13日は「元」、9月30日は「卅」、7月12日は「文」）。

二つの末尾が変則的に見えた。7月19日は「皓」（4110）ではなく 4210 で終わる。これは一文字の誤りで、第二の系統によって説明がついた（第6段階）。6月30日付の電報は「卄」（20日）で終わる。読みは画像で再確認済みで、食い違いは符号化の誤りか、20日起草・30日発信のいずれかである。

なぜ信じられるのか：対照検証

あらかじめ定めた基準結果
同形式の正の対照が復元されるはい（1,203〜1,216、鍵を復元）
記録のスコアが零の対照を明確に上回るはい（829 対 約335、再読後は1,144）
異なる初期値から同じ最適解が得られるはい（シード3つで同一）
検証用電報が調整なしで読める（1字あたり ≥ +2.5）はい：G0 で +3.99
中国語として通り、用紙の日付と整合するおおむね。351字中12字が疑わしい（ほかに稀だが確認済みの6字）
独立した外部からの裏付けはい：発信者「伸」＝趙伸。同じ兵器契約を扱う2026年の研究[7]によって、解読の後に同定、その後電報用紙（趙伸の氏名と住所）で確認
第二の系統：閉じた鍵の下で検証用電報が読めるはい：0496a は Y0 で +4.62、蔡鍔の八日福岡での死去を告げる
第二の系統：アンカー以外の日付末尾が用紙と一致はい：4通中4通

最後の点は強調に値する。趙伸の名、「第二次分の兵器」の引き渡し、広東による担保拒否、雲南と広東の間の兵器配分は、承紅磊の論文を読む前に、解読された電報の中に現れていた。これらの語は一つとして探索に注入されていない。

限界：G0 表は当てはめの表から読み取ったもの、Y0 表は五つのアンカーから導いたもので、天から降ってきたわけではない。最後の数回の読みはブラインドではない。訳は作業訳である。

第6段階 ―― 第二の系統と Y0 表

別の電報用紙の群は「文密」の名を持たないが、同じ発信者のもので、多くは平文の標識「Cg」で始まる。1916年7月から11月にかけて東京と雲南の間でやりとりされた15枚で、趙伸の署名があるか、彼に宛てられている。アルファベットが異なり、y が母音で、G0 では何も出てこない。位置の検定は同じ座標構造を示す（子音 z ≈ 22、母音 z ≈ 5）が、焼きなまし法による4回の探索（E26〜E29）は、人間の読みと日付アンカーを用いても否定的だった。ソルバーは正の対照を完全に復元するのに、検証用電報（0496a）は1字あたり +0.9 前後にとどまり、閾値 +2.5 に遠く及ばない。

突破口は、電報の冒頭と末尾を人間が読んだことから開けた。

  • 11月5日の電報（0489b）は平文で送られていた：十號起程月末抵滇 伸 歌（「十日出発、月末に雲南着；伸；五日」）。同日の暗号電報は buky hary で終わる。buky ＝「伸」（0135）、hary ＝「歌」（2960、五日の韻目）。
  • 11月11日の電報は foha ＝「尤」（1429、十一日の韻目）で終わる。

この五つの値（bu = 01、ky = 35、ha = 29、ry = 60、fo = 14）は、ある線形の音節表にぴったり当てはまる。c・j・q を除くアルファベット順の17子音、蛇行する6母音、値 ＝ 6 × 子音の順位 ＋ 母音の順位。アンカーで決まらなかったのは e と i の順序だけで、解読の前に対称性から定めた（機械判読では、逆にした変種は1字あたり +2.76、Y0 は +4.23）。

ルールについて二点。Y0 のアンカーは同日の平文電報、つまり推測ではなく文書から得たものである。一方、「ありそうな語」（「電」）を試したことがある。これはクリブ禁止ルールからの公表済みの逸脱であり、何の改善ももたらさず、却下された（E29）。また、この系統の本文は人間のブラインド再読をすべて終え、語数もすべて用紙の記載と一致する。それでも第一の系統ほど確かではなく、多くの稀な字がなお明示されている。

この系統は第一の系統の訂正にも役立った。7月19日の肇慶宛て電報はありえない符号で終わっていたが、同日に雲南へ送られた「双子」の電報はきちんと「伸皓」（十九日）で終わる。画像で確認すると、誤った文字は e ではなく i だった。モールス符号では e は ·、i は ·· である。

なぜ1916年5月は訂正した文字が多いのか

校訂文で角括弧に入れたのは、用紙が別の文字で書いている、または書き落としている文字である。その割合は1916年5月（611文字中109、17.8%）が1915年（1061文字中59、5.6%）の三倍で、二枚にわたる5月12日の電報だけでその半分を占める（234文字中56）。私はこれらの文字を一つずつ、期待される文字を見ながら画像で確かめた（2026年10月15日）。133文字のうち99は用紙に確かに別の文字で書かれており、18は期待される文字として読むことができ、16はなお不確かである。 この統計と以下の比較は、2026年10月15日に確認した初期標本を対象とし、1915年3月6日・7日の追加分を含まない。

方法の違いでは、ほとんど説明がつかない。1915年の校訂文は二つの独立した読みを組み合わせ、1916年のものは私一人の読みによる。しかし読み手を同じにして——1915年の私のブラインドの読みだけで——比べると、期待される暗号文とのずれは1915年が約7%、1916年が18%である。1916年の用紙のほうが不正確で、ずれは三組の文字に集中している：

これらの誤りは送信によるものではない。モールス符号では n と v、i と r、h と y に共通点はない。誤りは誰かが筆記体を読むときに生じる——おそらく窓口の係員が発信者の手書きの電文を書き写すときである——そして、ほぼ常に同じ向きである。期待される v は n になるが逆はなく、h は y になるが逆はない。原因は二つ考えられるが、どちらとも決められない。一つは急いで書かれた電報であること。1916年5月、孫文は上海から蜂起を指揮しており（“now very busy”）、暗号化そのものもより雑で、語全体が平文のまま残され（know、own、iron、trunk）、半分だけの語さえある（anxi-ous）。もう一つは係員の違い。上海の電信係は自分のものではないラテン文字の筆跡を読んでいた。ただし、東京から出た宋慶齢の二通の電報にも同じ誤りがある。

鍵そのものが影響を大きくしている。この鍵はまさに形の似た文字どうし（a/u、c/s、e/o、h/y、i/r、l/t、n/v…）を入れ替えるので、筆のわずかなためらいでも、見た目にはもっともらしいが解読には誤った文字が生まれる。1916年の鍵は確かに1915年のものである。自動探索で最初に見つかった変種（v↔p、n・i・r はそのまま）はこれらの誤りによる見かけにすぎず、平文のすべての v と矛盾する。用紙はそれを n と書き、p と書くことは一度もない。

私たちの知る限り、この方式もこれらの文も未発表である。Daniel Bourdeau の覚え書き[2]、Cryptiana[8]、二人の結婚に関する研究[18][19]、J. Chang と J. Halliday の伝記[20]のいずれにも見当たらない（2026年10月15日確認）。

延長：1916年5〜6月、既知の鍵で新たな電報を読む

ここでは鍵は新しくない。1916年5月の東京→上海（「Junzaburo」）の電報は「山田」圧縮符号で暗号化されており、すでに特定・公開されている[1, 2]。新しいのは電報そのものである。公開された翻字は JACAR B03050089100（5月末）で終わっている。逓信省のその後の送付分（B03050089000、B03050089200、B03050089400）を開き、同じ系列の5月17日から6月15日までの、未翻字の電報10通を見つけた。

方法は調査全体の逆向きの適用である。鍵が分かっているので、すべては文字の判読にかかる。Claude が画像から各用紙を読み、意味の通らない字があれば、1文字ずつ（筆写やモールスの取り違え）変えて文が通る文字を探した。それを私が、何を探しているかを承知のうえで画像と一つずつ照合した（V1〜V6、約40か所。大半が確認され、少数は否定されて疑わしいまま残した）。鍵とは独立の検証：韻目の日付が用紙と一致し、署名持（謝持）が繰り返し現れ、言及される人物（席正銘、趙瑾卿、廖仲愷、居正、萱野）は実在し、同じ人脈に属する。結果は電報のページを参照。

1916年5月上旬：上海からの返電。5月上旬の束には、東京発の電報のほか、上海から東京への返電がある。同じ「山田」鍵を逆向きに使って読め、うち1通は文の署名である。上海へ転送されたマニラ発の電報もあり、既発表のマニラ→頭山鍵[1]で読める。疑わしい語は Brice Dudout が画像と照合した。

5月10日の「w」：あえて採る読み、そして手がかり。5月10日の用紙（0042a）では、暗号作成者が「山田」表で p のはずの箇所に二度 w を書いている（「xetuwotedi」「rusidewari」）。同じ用紙には p も使われている。「山田」のアルファベット（子音20、w なし）に w はなく、書き損じとも考えにくい。そこで我々はこれを意図的な選択として扱う：w は p のもう一つの書き方（同音異字）であり、電報のページではこの電報を w = p とした「山田」表で読み、文字は書かれたとおりに示す。w の20通りの値のうち p の値がはっきり最良で、「昨日到」と「乘原船」を与える唯一の値である。表の他の部分は変わらない（署名持と日付灰（10日）が合う）。同じ用紙の k 二つも p の代わりらしい（事、灰）が、提案にとどめる。その後、wの手掛かりは結果につながった。指示語のない東京発と「Ylchang」宛ての上海発から、子音順を入れ替えた黄興の表が得られた。同節に記すとおり、これで読めない電報も残る。一方G0は上記の逆順アルファベットに従う。

ホノルル：鍵の「Aloha」変種。4月30日のホノルル発の電報（平文の前置語「Aloha」、宛名「Rosamonde」すなわち孫文）は、圧縮符号のアルファベットにない w を v と並べて用いる。既発表の「ホノルル」鍵[1]で、w に v の値を与えると読める。同じ文字のもう一つの書き方であり、5月10日の p に対する w と同様である。これをこの鍵の「Aloha」変種として示す。電報は鐵城（呉鉄城、当時ホノルル在住）の署名で、「黃轉到日，換船赴滬。鐵城」（「黄〔興〕は日本へ回り、船を乗り換えて上海へ向かう」）と読める。3文字を送信誤りとして訂正し（r が s として受信されたのが2回、e が o として1回）、冒頭の黃は文脈から補った。黄興は5月9日に日本に着く（電報0042a）。

同時期の二つの系統は読めないように見えた。「Thirtyseventh」の前置きのない東京発の電報（互いに文字列の反復を共有する）と、上海から「Ylchang」（黄興）への電報である。実際には両者とも同じ一つの新しい表で読める。黄興の表を参照。

新しい表「Thirtyeight」（1916年5月）

5月上旬の東京発の電報2通は、「Thirtyseven」ではなく別の平文の前置語「Thirtyeight」を持つ。鍵によらない検定では同じ型の表（2文字 → 2数字）だが、「山田」鍵では読めない。圧縮符号表の族（子音の起点、母音の順序と向き、オフセット：57,600表）を探索すると、一つがはっきり首位に立つ（z = 6.7）：子音はアルファベット順に k から、母音は e a i u o、値 = 20 × 母音の順位 + 子音の順位 + 1（100を法とする）。「山田」と同じ構成（子音は q から、母音は e u i o a）で、パラメータだけが異なる。この表は一つのマスも変えずに5月12日の電報を読む：「箱已交犬塚，十五日附法船來。若有要事，請電如下」（「箱は犬塚に渡した。15日にフランス船で送る。急用があれば次へ打電されたい」）。続いて平文の宛先がある。訂正は1文字のみ（d → x、他でも見られる写し誤り）。管見の限り、この表は未公表である。もう1通の「Thirtyeight」電報（5月11日）も読める：「聞張繼已回日，頗奇，是否？」（「張継が日本に戻ったと聞いた。たいへん意外だ。本当か」）。訂正は1文字（o → e）。

第二の新しい表：黄興の表（1916年5月末〜6月）

1916年5月26日から6月6日にかけて、東京から「Junzaburo」（上海）宛に、前置語「Thirtyseven」のない電報が送られた。既知の表ではどれも読めなかった[2]、[8]が、二つの観察が探索の手がかりとなった。6月6日の電報は6月3日の電報の後半を符号ごとに繰り返し、送信で失われた9符号を補っている。また3通の電報は日付にかかわらず同じ2符号で終わる。これは日付（謝持の「持」に韻目を続けるような）ではなく、結びの語と署名である。

黄興の別の電報（1916年5月25日、林虎・李根源宛）の三仮名コードとは別物である。その方式は D. Bourdeau が、対応の公式は S. Tomokiyo が明らかにした[22][23]。

鍵なしの検定では座標型の表（子音が十の位を担う）が示されていた。そこで焼きなまし法により、20の子音それぞれが連続する5つの値のブロックを任意の順で占め、母音は共通または交互の順に並ぶ表を探した。探索はまず較正した。すでに読めた電報をこの族の無作為な表で暗号化し直したものは、完全に復元された（12通中12通）。東京発の電報6通（140符号）では、独立した6回の試行がすべて同じ表に達し、対照（同じ音節を混ぜたもの）を大きく上回った：1符号あたり4.26対0.73。

表は非常に規則的である。子音の順は d c b t h j f q g k n m p s r l x w z v、それぞれ連続する5つの値を占め、01〜99、ついで00と番号づけられる（du = 01、di = 02 … va = 00）。母音の順は u i o e a。東京発の電報はすべて覆。興（「返電を。興」）で終わる。5月9日から東京にいた黄興である。一つの欄も変えずに、同じ表は上海から「Ylchang」（黄興）宛の、文または孫文（孫文）署名の電報も読む。6月6日の電報は日付魚（6日）で終わり、用紙の日付と一致する。

内容：6月3日、黄興は田中（田中、おそらく参謀次長田中義一）に会い、「槍二千、砲六門不日可運」（小銃2000挺と砲6門を近日中に送れる）。5月31日、資金20万と武器若干、胡漢民（漢民）に青木（青木）へ当局に再び打電するよう頼ませた。〔日本側は〕孫文が急いで山東へ赴くことを望まず、黄興は張継（溥泉）と声望ある軍人による調停を提案する。9通が読めた。疑わしい文字はBrice Dudoutが用紙上で確認し（意味を知らない読み）、電報は電報ページに掲載した。上海から「Ylchang」宛の2通（5月29日、6月8日）は別の発信者のもので（冒頭と末尾の符号が共通）、この表では読めない。

別系統の歴史的暗号：「共密」電報

これらの電報は、上で説明したG0・Y0の表を使っていない。平文の電信接頭辞共密で区別できるが、この接頭辞だけでは、同じ接頭辞を持つ全電報に共通の歴史的鍵が使われたとは証明できない。

候補モデルC51は数字群を次のように読む。各用紙を列ごとに右から左、上から下へ読み、次の用紙へ続ける。平文の公開接頭辞0364 1378を一度除く。十の位を下表で置き換え、通常の繰り下がりでP = (9000 − 正規化したC) mod 10000を計算し、Pを中国電碼（CTC）で引く。

数字C0123456789
φ(C)9761405283

この規則でN17とN18から解釈可能な中国語の断片が得られる。ただし候補復元であり、1916年に実際に使われた暗号帳は特定されていない。印刷版CTCとは対象14項目が一致するが、当時の使用版を証明するものではない。スキャンと読みの不確かさはN17・N18の部分校訂版を参照。

第三の系統：「容密」電報

1916年6月に東京（張孝準・黄興）と上海（浙江督軍呂公望・殷汝驪・葛敬恩・黄郛）の間で交わされた電報14通は、平文の前置き1369 1378、すなわち中文電碼の容密で始まる。残りは共密とは別の鍵で暗号化されている。解読は四段階である。

1. 数字を読む。共密と同じく、各用紙を列ごとに右から左へ、各列を上から下へ読み、次の用紙に移る（Brice Dudoutの提案した順序）。数字の流れを4桁ずつ区切る。最初の2組は前置きでそのまま残す。

2. 各桁を位ごとに置き換える。千・百・十・一の位にはそれぞれ置換表がある：

読んだ数字0123456789
千の位0123456790
百の位0123456789
十の位0198276543
一の位9801723456

百の位は変わらない。千の位では8と9だけが変わり、8は9、9は0となる。後者の理由は単純で、資料中に「00」で始まる組はなく、暗号作成者は代わりに「90」と書いた（0が二つ続く組を避けるためか）。

3. 通常の繰り上がりで0901を加える。得られた数に0901を筆算のように加え、位から位へ繰り上げ、下4桁を残す。繰り上がりは重要で、桁ごとに繰り上がりなしで足すと別の字になる。

4. 結果を中文電碼（CTC）で読む。4桁の数がそれぞれ一字に対応する。

例

読んだ組σ（段階2）＋0901結果CTC
20812048＋09012949款
33083305＋0901（百の位の繰り上がり：3＋9＝12）4206督
90520070（90＝00の規則）＋09010971均

鍵の発見。容密電報は最初の用紙（90組）しか翻字されておらず、統計的方法には少なすぎ、以前の試みは失敗していた。2026年10月、所在は分かっていたが未翻字だった続き用紙を読み、再読後で約600組となった。この資料では、桁ごとの4つの置換（位ごとに一表、共密に対するCodexの最初の試みと同じ）で読める文が得られ、攪拌した対照を大きく上回った。続いてある異常から加算が判明した：「借款」（2949）がときに千違いの「借甸」（3949）になり、それは百の位の加算で繰り上がりが生じない場合に限られた。正確な鍵（表＋繰り上がりつき0901）は4通で計算し、「90＝00」の規則は、90で始まる組がすべて不合理な字になり、00で始まる組が一つもないことに気づいて後から加えた。

検証。（1）N02・N08・N11・N12で見つけた鍵は、再調整なしで他の7通を読む。その一つN14は黄興の署名で、日付の韻目佳（9日）が用紙の見出しと一致する。（2）Brice Dudoutが再読した全体（590組）で再調整しても同じ表に戻る。（3）解読を見ずにBrice Dudoutが行った読みの訂正は、この鍵のもとで文を改善する。（4）得られた人名は1916年6月に該当する役職にあった実在の人物と一致する：張国淦、谷鍾秀（九峯）、張孝準（字潤農）。（5）末尾の日付の韻目は用紙の日付と一致する（N14、N21、N36）。

限界。鍵は復元であり、1916年にどう記されていたか、使われた電碼本が参照した印刷版CTCと同一かは分からない。いくつかの符号は予想外の字で繰り返し現れる（生に繒、盼に盻）。これらは明示し、訂正はしない。解読プログラムはsolver/rongmiに、電報は容密のページと電報一覧にある。

第四の系統：「辰密」電報

1916年6月に黄興と張孝準が東京から上海の電信あて名「ヒツキン」（霞飛路277、湖南派のあて先）に送った電報4通は、平文の前置き6591 1378、すなわち辰密で始まる（N05には前置きがない）。この名は黄興の電稿の刊本にも、湖南の同志あてとして見える。ここでは定数の加算はなく、電碼そのものが並べ替えられている。

1. 数字を読む：共密・容密と同じく、列ごとに右から左、上から下へ（Brice Dudoutの提案した順序）、4桁ずつ。

2. 最初の2桁が頁を示す。CTCは百字ずつの頁（0000〜0099、0100〜0199…）に並ぶ。辰密では頁を逆順に、0を含む数を飛ばして数える：99が00頁、98が01頁、…、91が08頁、次に89が09頁（90は飛ばす）、以下11＝80頁まで。

暗号の頁99989796959493929189…11
CTCの頁00010203040506070809…80

最初に目を引いたのはこの点で、これらの電報では千の位・百の位に0が一度も現れない。

3. 後の2桁が頁の中の位置を示す。十の位と一の位をそれぞれ置き換える：

読んだ数字0123456789
十の位3987102645
一の位19543267810

一の位の9は「10」で、通常どおり十の位に繰り上がる。4. 結果 P＝100×頁＋10×十の位＋一の位をCTCで読む。

例

読んだ組頁十一結果CTC
995099 → 005 → 00 → 10001一
422042 → 522 → 80 → 15281興
621962 → 341 → 99 → 103500灰

鍵の発見。共密・容密の系統の試みは失敗し、辰密には既知の平文がなかった。手がかりは二つ：最初の2桁に0がないこと、組が少数の「頁」に集中すること（99・96・93で全体の4分の1）で、頻度順に並べた本を思わせる。N13・N16・N26（201組）に「頁の置換＋十の位・一の位の置換」のモデルを当てはめた。厳密な割当て法は偽の最適解にとどまり、焼きなまし法が攪拌した対照を大きく上回る読める文を見つけた（較正3/3）。得られた頁表は0を含まない逆順に従っていたので、それを課した。9で終わる組から来る二つの異常字（力に劈、灰に滠）から「9＝10」の規則が分かった。

検証。（1）探索に使わず前置きもないN05が、この鍵でそのまま読める。（2）見出しが10日のN16は10日の韻目灰で終わる。（3）N16は「昨日、克強が打電して…」と述べ、前日に黄興が署名したN13の依頼を繰り返す。（4）人名は1916年の湖南の実在の人物：趙夷午（趙恒惕）、湯督（湯薌銘）、濟武（湯化龍）。（5）十の位・一の位の表のどの入れ替えも文を改善しない。

限界。1916年にこの暗号がどう記されたか、本が参照CTCに正確に従っていたかは分からない。4字は1桁違いの推定読みで、N13の「一不」はおそらく「不一」の転倒で、N05の「盻」は容密と同じく文脈から「盼」と読む。解読プログラム：solver/chenmi、電報：辰密のページと電報一覧。三系統の独立検証用（再読した数字、本文の再現、対照つきの鍵探索）：solver/numeric1916。

番号を付け替えた本：S. Tomokiyo氏の着想と「乾密」電報

着想。2026年10月23日、S. Tomokiyo氏（Cryptiana）は、私たちの三つの数字鍵を1916年の電信係のやり方で読み直すことを提案した。計算ではなく、頁・列・行の番号を手書きで付け替えた「明密」電碼本を使ったというのである[22]。私たちはこれを確かめた：10,000通りのすべての組について、共密・容密・辰密の鍵は頁（上2桁）・列（十の位）・行（一の位）に正確に分解でき、10行目は各列の最下段のxxx0である。頁の番号は逆順（共密）、10頁から循環（容密）、0を含まない数（辰密）。着想とこの再定式化は同氏のものであり、本サイトの各鍵のページにそう記している。

私たちの発見。「X密」の本がこうした番号付けだけで異なるのなら、同じモデルで未解読の電報も開けるはずである。各電報について、単純な頁の規則（逆順・循環・0なし、起点は自由）と、列と行の二つの自由な置換を探し、言語モデルで当てはめた。実際の電報で計算する前に手順を定め、同じ長さでこの型の鍵により暗号化した合成電文（方法が復元できるはずのもの）と、攪拌した数字（何も見つからないはずのもの）と比べた。

黄興の東京の家から出た、前置き乾密のN09がはっきり抜きんでた（4.47、最良の対照は2.88）。鍵は頁＝書かれた頁−11、さらに：

読んだ数字0123456789
列6732804951
行76214938105

本文は「袁死。此間態度未變，候交涉有望，再電告。興」（袁死す。当地の態度は変わらない。交渉に望みが出るのを待って改めて打電する。興）と読める。期待どおり署名「興」で終わり、袁世凱の死（6月6日）で始まり、綴りの中の位置と合う。異常な3字（卵・侯・命）はBrice Dudoutが画像上で2回、2回目は盲検で読み直し、数字は確かである。未（1桁違い）、候・告（文脈）と読む。
